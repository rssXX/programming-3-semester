## Цель работы

Разработать веб-приложение с двумя веб-формами и базой данных: списком студентов и формой добавления/редактирования. Реализовать аналогичный функционал для учебных групп и диагностические методы мониторинга приложения.

## Описание задачи

Методические материалы предлагают Spring Boot, Spring Data JPA, H2 и Thymeleaf. В соответствии с подходом предыдущих лабораторных задание выполнено на собственном стеке: TypeScript, Bun, Elysia и SQLite. Все лабораторные находятся в репозитории programming-3-semester в одной ветке main. Изменения ЛР7 размещены в src/routes/lab7 и отмечены комментариями «ЛР7».

Основное задание: создать таблицу студентов с полями id, name, surname, faculty, age; реализовать серверную часть и две страницы — список и форму. На странице списка должны быть доступны создание, изменение и удаление. Записи должны сохраняться в файловой БД.

Дополнительное задание: добавить сущность учебной группы, её контроллер, форму и список с аналогичными операциями. Предоставить методы, выполняющие роль Spring Boot Actuator. Скриншоты добавляются автором отчёта самостоятельно.

### 2. База данных

Студенты используют таблицу students из ЛР6 и существующие StudentServiceImpl и SqliteStudentDAO. Новое веб-приложение и REST API читают одни данные: изменение через форму сразу видно в /api/v5/students.

По умолчанию файл расположен в testdb/students.sqlite. Путь переопределяется переменной DATABASE_PATH. Схема выполняется в транзакции при первом обращении к БД. CREATE TABLE IF NOT EXISTS добавляет таблицу групп к существующей БД без удаления студентов и дисциплин. Соединение закрывается при остановке приложения.

Листинг 1. Таблицы студентов и учебных групп (src/database/schema.sql):

```sql
CREATE TABLE IF NOT EXISTS students (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL CHECK (length(trim(name)) BETWEEN 1 AND 15),
    surname TEXT NOT NULL CHECK (length(trim(surname)) BETWEEN 1 AND 25),
    faculty TEXT NOT NULL CHECK (length(trim(faculty)) BETWEEN 1 AND 20),
    age INTEGER NOT NULL CHECK (age BETWEEN 0 AND 150)
) STRICT;

CREATE TABLE IF NOT EXISTS study_groups (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL CHECK (length(trim(name)) BETWEEN 1 AND 30),
    faculty TEXT NOT NULL CHECK (length(trim(faculty)) BETWEEN 1 AND 20),
    course INTEGER NOT NULL CHECK (course BETWEEN 1 AND 6)
) STRICT;
```

Методичка не определяет поля учебной группы. Выбраны обозначение группы, факультет и курс 1–6. Связь студента с группой не требуется заданием; таблицы независимы. Пример группы: РИЗ-250213у, ИРИТ-РТФ, курс 2. Команда db:seed добавляет этот пример без дублирования при повторном выполнении.

Для просмотра записей в DBeaver необходимо выбрать SQLite и абсолютный путь к файлу. После отправки формы следует обновить данные таблицы students или study_groups.

### 3. Контроллеры и сохранение форм

| Метод | Студенты | Учебные группы | Действие |
| --- | --- | --- | --- |
| GET | /list | /groups | Список записей |
| GET | /addStudentForm | /addGroupForm | Форма создания |
| GET | /showUpdateForm?studentId=1 | /showGroupUpdateForm?groupId=1 | Форма с данными записи |
| POST | /saveStudent | /saveGroup | Создание или изменение |
| POST | /deleteStudent | /deleteGroup | Удаление |

Корневой адрес / перенаправляет на /list. Для изменения форма содержит скрытое поле id. Если id пустой, создаётся запись с автоматически назначенным идентификатором; иначе обновляется существующая. Обновление отсутствующего id возвращает 404 и не создаёт новую запись.

Листинг 2. Обработчик сохранения студента (src/routes/lab7/students.ts):

```typescript
.post('/saveStudent', ({ body, redirect }) => {
    const form = new FormInput(body)
    const student = {
        name: form.text('name', 'Имя', 15),
        surname: form.text('surname', 'Фамилия', 25),
        faculty: form.text('faculty', 'Факультет', 20),
        age: form.integer('age', 'Возраст', 0, 150),
    }
    const id = form.optionalId()
    if (form.invalid) return html(studentForm(form.values, form.errors), 400)
    if (id === undefined) service.create(student)
    else service.update({ ...student, id })
    return redirect('/list?status=saved', 303)
}, { parse: 'urlencoded', detail })
```

Применена схема Post/Redirect/Get: после успешного POST сервер возвращает HTTP 303 с адресом списка, затем браузер выполняет GET. Обновление открытого списка не повторяет создание записи. Удаление также выполняется POST и завершается перенаправлением. GET по адресу удаления не меняет данные.

### 4. Сущность и DAO учебных групп

Листинг 3. Сущность учебной группы (src/routes/lab7/groups/entity.ts):

```typescript
export interface StudyGroup {
    id: number
    name: string
    faculty: string
    course: number
}
export type StudyGroupData = Omit<StudyGroup, 'id'>
```

StudyGroupDAO задаёт findAll, findById, create, update и delete. SqliteStudyGroupDAO реализует эти операции. StudyGroupService обрезает пробелы по краям строк и обрабатывает отсутствие записи, а контроллер отвечает за HTTP и отображение HTML.

Листинг 4. Создание группы в DAO (src/routes/lab7/groups/dao.ts):

```typescript
create(group: StudyGroupData): StudyGroup {
    return this.connection.database.query<StudyGroup, [string, string, number]>(
        'INSERT INTO study_groups (name, faculty, course) VALUES (?, ?, ?) RETURNING id, name, faculty, course',
    ).get(group.name, group.faculty, group.course)!
}
```

Пользовательские значения передаются отдельно от SQL. Аналогично реализованы параметризованные UPDATE, DELETE и поиск по id. Первичные ключи студентов, групп и дисциплин независимы.

### 5. Клиентские формы и проверка данных

Список студентов показывает имя, фамилию, факультет и возраст. Список групп показывает обозначение, факультет и курс. Для каждой записи доступны кнопки «Изменить» и «Удалить». Если записей нет, выводится пояснение и остаётся доступна кнопка добавления.

Для каждой сущности используется одна форма создания и редактирования. Страница содержит подписи полей, ограничения required, maxlength, min, max и step, кнопки сохранения и отмены и ссылку назад. Оформление хранится локально, страницы адаптируются к узкому экрану.

Листинг 5. Основная структура формы студента (фрагмент серверного шаблона):

```html
<form action="/saveStudent" method="post">
    <input type="hidden" name="id" value="">
    <label for="name">Имя</label>
    <input id="name" name="name" type="text" maxlength="15" required>
    <!-- Аналогичные подписанные поля surname, faculty и age. -->
    <button type="submit">Сохранить</button>
    <a href="/list">Отмена</a>
</form>
```

На сервере отдельно проверяются обязательность, длина текстов и диапазоны целых чисел. Пустое числовое поле не превращается в ноль. При ошибке сервер возвращает HTTP 400 с той же формой, сохранёнными значениями и сообщениями у ошибочных полей. Отсутствующая запись возвращает HTML 404, ошибка работы с БД — HTML 500. Технические подробности ошибки БД остаются в серверном логе.

Функция escapeHtml заменяет специальные символы перед включением данных в текст и атрибуты HTML. Поэтому введённые HTML-теги отображаются как текст. Валидация браузера дополняется серверной проверкой и ограничениями SQLite.

### 6. Диагностика — аналог Actuator

Собственные маршруты мониторинга реализованы в src/routes/lab7/monitoring.ts. Это адаптация учебной задачи к Bun и Elysia, а не подключение Java-библиотеки Spring Boot Actuator.

| Метод GET | Назначение | Ожидаемый результат |
| --- | --- | --- |
| /actuator | Ссылки на методы | Объект _links |
| /actuator/health | Проверка соединения с SQLite | UP и HTTP 200 либо DOWN и HTTP 503 |
| /actuator/info | Информация о приложении | Название, ЛР7, стек, версия Bun, startedAt |
| /actuator/metrics | Список метрик | process.uptime, process.memory.usage |
| /actuator/metrics/process.uptime | Время работы процесса | Число секунд |
| /actuator/metrics/process.memory.usage | Использование памяти RSS | Число байтов |

Проверка health выполняет реальный SELECT 1 в используемой БД. При недоступном файле она отвечает DOWN и не раскрывает путь или текст внутренней ошибки. Метрики вычисляются при запросе через process.uptime() и process.memoryUsage().rss, их значения зависят от запуска. Неизвестная метрика возвращает 404.

### 7. Запуск и ручная проверка

Команды для Windows PowerShell из корня репозитория:

```powershell
bun.cmd install
bun.cmd run db:init
bun.cmd run db:seed
bun.cmd run start
```

Заполнение db:seed необязательно; формы работают и с пустыми таблицами. Использование bun.cmd позволяет запускать команды без изменения политики PowerShell. Для выбора другого файла перед командами можно задать $env:DATABASE_PATH = 'testdb/lab7.sqlite'.

Порядок проверки:

1. Открыть http://localhost:8082/list и нажать «Добавить студента».
2. Ввести имя, фамилию, факультет и возраст, сохранить. Проверить появление строки в списке и таблице students в DBeaver.
3. Нажать «Изменить», изменить возраст, сохранить и проверить новые данные.
4. Перезапустить приложение и убедиться, что запись сохранилась.
5. Удалить созданную запись и проверить её отсутствие.
6. Открыть http://localhost:8082/groups и повторить создание, изменение и удаление учебной группы.
7. Проверить методы /actuator в браузере или импортировать postman/lab7.postman_collection.json в Postman и выполнить коллекцию.
